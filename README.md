# 💗 Recharge Club

**Your energy. Your rules. Your pink era.**

Персональний трекер енергії, настрою та відновлення в естетиці Barbiecore Wellness. Допомагає помічати свій суб’єктивний ресурс, знаходити заняття, після яких тобі краще, і будувати власну бібліотеку відновлення — без тиску, streaks і «треба».

> Рівень енергії в застосунку — це суб’єктивна самооцінка, а не вимірювання організму. Recharge Club не ставить діагнозів і не замінює професійну допомогу.

## Найпростіший запуск — один HTML-файл

Завантаж файл [`standalone/recharge-club.html`](standalone/recharge-club.html) і відкрий його подвійним кліком у браузері (Chrome, Edge, Firefox, Safari). Нічого встановлювати не потрібно: увесь код, стилі й шрифти вбудовані у файл, інтернет не потрібен.

Дані зберігаються в браузері окремо для кожного розташування файлу: якщо перемістити файл в іншу папку, браузер вважатиме його новим «сайтом». Тому тримай файл в одному місці, а для перенесення даних користуйся експортом/імпортом JSON у профілі.

Перезібрати файл після змін у коді: `npm run build:html`.

## Запуск для розробки

Потрібен Node.js 20+ (перевірено на Node 22).

```bash
npm install
npm run dev        # режим розробки → http://localhost:5173
npm run build      # перевірка типів + продакшн-збірка в dist/
npm run preview    # перегляд продакшн-збірки
npm test           # юніт-тести (бібліотека, фільтри, рекомендації, аналітика, сховище)
```

Збірка статична (`base: './'`), тож `dist/` можна викласти на будь-який статичний хостинг (GitHub Pages, Netlify, Vercel, S3).

## Стек

React 19 · TypeScript (strict) · Vite 7 · Tailwind CSS 4 · Recharts 3 · date-fns 4 (українська локаль) · lucide-react · самохостинг шрифтів Unbounded + Manrope (з кирилицею, без запитів до сторонніх серверів) · Vitest.

### Як працюють рекомендації

`src/lib/recommend.ts`. Без вигаданих «наукових балів»: оцінка складається з відповідності поточному стану та сценарію (контекстні теги, зусилля, тривалість, формат), налаштувань профілю й **особистої історії** (зміни до/після, «хочу повторити», оцінки). Жорстко виключаються приховані заняття, «не моє», небажані категорії, заняття довші за доступний час або важчі за доступну енергію. Перший прохід бере по одному заняттю з категорії, щоб варіанти були різноманітними.

### Аналітика

`src/lib/insights.ts`. Усе рахується лише зі збережених записів. Висновки з’являються, коли спостережень достатньо (≥ 4 у групі та ≥ 8 загалом), сформульовані як кореляції («частіше збігалося»), з розміром вибірки й періодом. Якщо даних мало — м’яке «поки недостатньо записів». Якщо настрій тривалий час дуже низький, з’являється м’яка пропозиція звернутися до фахівця (без діагнозів, із можливістю сховати).

### Психологічна безпека

Немає streaks, рейтингів і покарань за пропуски; бейджі відзначають дослідження («спробувала щось нове», «знаю, що мені не підходить»), а не регулярність чи високі показники. Порожні дні — просто порожні дні. Погіршення після заняття — «теж цінна інформація».

### Демо-дані

Генеруються детерміновано (`src/data/demo.ts`) і зберігаються **окремо** від реальних (`state.demo` vs `state.real`). У демо-режимі на кожній сторінці є банер, а статистика позначена як демо. Очистити демо можна з банера або в профілі; CSV-експорт містить лише реальні дані.

## Дані та приватність

- Усе зберігається в `localStorage` цього браузера (ключ `recharge-club:state`), зі схемою версій, санітизацією та резервною копією, якщо збережені дані пошкоджені.
- Жодних серверів, акаунтів, аналітики чи сторонніх запитів (шрифти теж локальні).
- Синхронізація між вкладками одного браузера.

## Структура

```
src/
  types.ts                 типізовані моделі (Activity, ActivityLog, DailyCheckIn, PlannedActivity, UserPreferences, PersonalInsight…)
  data/activities/*.ts     бібліотека занять (компактний формат, по файлу на категорію)
  data/{categories,labels,notes,demo}.ts
  store/                   стан, збереження, санітизація, міграції
  lib/                     фільтри, рекомендації, аналітика, бейджі, дати, експорт, нагадування
  components/              UI-кіт, батарейка, картка та екран заняття, форми, макет
  pages/                   Home, Activities, Calendar, Insights, Coach, Profile, Onboarding
  __tests__/               юніт-тести
```

**Як розширити бібліотеку до 500–1000 занять:** додавай рядки в кінець відповідного файлу в `src/data/activities/` (ID генеруються з порядку, тож нові записи лише в кінець) або створи новий файл категорії й підключи його в `index.ts`. Тест `library.test.ts` перевіряє унікальність ID, назв і описів та коректність усіх полів. Фільтрація лінійна й мемоізована, список рендериться порціями по 24.

## Обмеження та що потребує налаштування

- **Синхронізація між пристроями не реалізована.** MVP працює локально без реєстрації. Для синхронізації потрібен бекенд (наприклад, Supabase: Auth + таблиці з Row Level Security, де кожна користувачка бачить лише свої рядки). Модель даних уже має стабільні ID й ISO-час, тож її можна перенести в таблиці майже один в один.
- **Нагадування** спрацьовують, лише коли вкладка відкрита (вебсповіщення без сервера push). Для фонових нагадувань потрібні service worker + Web Push і сервер, що надсилає повідомлення.
- **Офлайн/PWA:** застосунок працює без мережі після завантаження, але маніфесту й service worker для встановлення на домашній екран поки немає.
- Дані зникнуть, якщо очистити дані сайту в браузері, тому для резервної копії використовуй експорт JSON.
